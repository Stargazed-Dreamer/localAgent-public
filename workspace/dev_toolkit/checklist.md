# 功能变更检查清单

> 新增功能、修改模块、重构代码后，按此清单逐项检查。
> 精简版：只保留对 agent 和开发者有实际影响的检查项。

## 代码变更

- [ ] 新增的模块/文件是否在 `AGENTS.md` 项目结构中反映？
- [ ] 修改了接口/函数签名？→ 对应 skill 的 SKILL.md（工作流+依赖）是否需要同步？
- [ ] 是否有硬编码的路径/端口/密钥？→ 移入配置文件
- [ ] 错误处理是否完善（不暴露内部细节给用户）？

## SDD 产物

- [ ] 本次变更是否有对应的 `.agents/specs/{feature}/` 产物？
  - 有 → 完成后是否在 spec 目录标记完成？
  - 无 → 是小修小补可以跳过，中等以上变更应补 spec
- [ ] spec.md 中的 DoD（完成标准）是否全部达成？

## 测试

- [ ] 新增的模块是否有对应测试？
- [ ] 已有测试是否因代码变更需要更新？
- [ ] 提交前测试是否全部通过？

## 文档同步

- [ ] `AGENTS.md` — 项目结构/技术栈/关键约束是否需要更新？
- [ ] `.agents/skills/_index.md` — 新增/修改/删除 skill 后是否同步？
- [ ] 对应 skill 的 `SKILL.md` — 工作流/坑点/规则是否需要更新？
- [ ] `.agents/rules/*.md` — 是否新增了规则需要 AGENTS.md 引用？
- [ ] `README.md` — 快速开始/项目结构是否需要更新？

## 记忆与 WIP

- [ ] 本次任务进度是否写入 `.agents/memory/{key}.json`？
- [ ] 任务中断？→ 触发 wip-tracker 留档
- [ ] 任务完成？→ 更新 wip 留档 status 为 completed

## 配置

- [ ] 配置模板（`.env.example`、`config.example.*`）是否同步更新？
- [ ] 新配置项是否有合理默认值？
- [ ] `.gitignore` — 新的敏感文件/目录是否已排除？

## Git

- [ ] 变更是否已提交？
- [ ] 提交信息是否描述了"为什么"而非"做了什么"？
- [ ] 是否避免提交敏感文件（密钥、配置、本地数据）？

## 收尾（可选）

- [ ] 触发 neat-freak（说"整理一下"）做文档同步审查
- [ ] 触发 verify（说"验证一下"）确认 DoD 全部达成
