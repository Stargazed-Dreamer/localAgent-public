# implement — 实现（照任务清单写代码）

## 触发词
实现、写代码、编码、implement、开始做、动手、开干、写吧、开始实现

## 概述

拿着 tasks.md 的任务清单，一条条照着实现。因为方向、方案、任务都提前敲定过，这里基本是个执行者，不太会自作主张乱改。

SDD 四台阶的第 4 阶（最后一阶）。

## ★ 防呆门（开头必查）

接到任何"写代码/实现/编码"类任务时，**第一步先查**：

### 检查 1：是否有对应规约？

读 `.agents/specs/` 下是否有相关 feature 的 spec.md + plan.md + tasks.md。

**有规约** → 照 tasks.md 逐条实现（进入下方"工作流"）。

**无规约** → 按任务规模分流：

| 任务规模 | 判断依据 | 处理 |
|---------|---------|------|
| 小修小补 | 改错别字、调样式、加一眼看穿的小功能、几十行一次性脚本 | **放行**，直接写，但说"这次跳过规约" |
| 中等以上 | 新功能、新模块、较大改动、要长期维护 | **拦截**，提示先走 SDD |

### 拦截话术（中等以上任务无规约时）

> 这个任务看起来要 [具体规模/影响]，直接写代码容易返工。建议先花几分钟走 SDD 流程把需求想清楚：
> 1. `grill-me` 审问澄清需求（5-15 分钟）
> 2. `spec` 写需求规约
> 3. `plan` 定技术方案
> 4. `tasks` 拆任务
> 5. 再回来 `implement`
>
> 要现在开始 grill-me 吗？还是你坚持直接写？

**用户坚持直接写**：可放行，但说清"这次跳过规约，后续要扩展/返工时建议先补 spec"。

### 检查 2：tasks.md 是否存在且已确认？

有 spec/plan 但**没 tasks** → 提示先走 tasks 拆任务，不要凭 spec/plan 直接写（容易漏）。

## 工作流（有规约时）

### 1. 读 spec.md + plan.md + tasks.md

完整读三份文档，确认要做什么、怎么做、按什么顺序。

### 2. 逐条实现 tasks.md

按 tasks.md 的顺序，一条一条做：

- 每条任务开始前，确认依赖任务已完成
- 按"改哪些文件 + 具体做什么"执行
- 每条做完，**立即按 tasks.md 里写的验证方式验证**
- 验证通过，在 tasks.md 把 `[ ]` 改成 `[x]`
- 验证失败，修复后重验，不要跳过

### 3. 遵守编码准则（coding_principles.md）

写代码时全程遵守：
- **Surgical Changes**：只动 tasks.md 要求的，不顺手优化别的
- **7 级阶梯**：先复用已有/标准库，再写新代码
- **Simplicity First**：不写没要求的抽象/配置/错误处理
- 每行改动都能追溯到 tasks.md 的某条任务

### 4. 分阶段提交（建议）

每完成一个阶段（tasks.md 里的阶段划分），建议提交一次，附验证结果。不要一口气全写完才提交——上下文太长容易顾此失彼。

> 大项目别指望一条 implement 命令从头撸完。先骨架+基本增删跑通、验一下，再往上加。

### 5. 全部完成后，主动建议进 verify

> tasks.md 全部完成。下一步建议跑 `verify` 做完成前验证（对照 spec 的 DoD 逐条确认）。要现在验证吗？

## 坑点清单（Gotchas）

- **跳过防呆门直接写**：没查规约就开写 = vibe coding 共谋。第一步必须查 specs/。
- **不按 tasks 顺序**：跳着做容易漏依赖。
- **不逐条验证**：做完一条不验证就写下一条，错了积压到最后爆雷。
- **顺手优化无关代码**：违反 Surgical Changes。无关的死代码提一句，不要删。
- **自作主张改设计**：tasks.md 没要求的功能不要加（YAGNI）。想加先回去改 spec/plan/tasks。
- **不更新 tasks.md 勾选状态**：做完不勾，不知道进度到哪了。
- **一口气写太多**：上下文太长容易顾此失彼，分阶段提交更稳。

## 关键规则

- **必须**开头查 `.agents/specs/` 是否有规约，无规约按防呆门分流。
- **必须**按 tasks.md 顺序逐条实现 + 逐条验证 + 逐条勾选。
- **必须**遵守 coding_principles.md（Surgical / 7 级阶梯 / Simplicity）。
- **绝不**写 tasks.md 没要求的代码（YAGNI）。
- **绝不**跳过验证直接写下一条。
- 中等以上任务无规约时**必须**拦截提示 SDD，用户坚持才放行。
