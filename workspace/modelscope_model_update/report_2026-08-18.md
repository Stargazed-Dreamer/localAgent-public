## ✅ 待核对项结论（2026-08-18 二次核实，已修正 keys.json）
3 个模型用真实 token 实测 + 直接抓取 ModelScope 模型页 `BackendSupport` 字段确认：

| 模型 | 真实 Model-Id | API 实测 | 模型页 SupportApiInference | 结论 |
|---|---|---|---|---|
| Ring-2.6-1T | `inclusionAI/Ring-2.6-1T` | HTTP 401 `ling_auth_not_exist` | **false** | 平台无 serverless 推理端点，需自部署（SGLang 多卡） |
| Hunyuan-Hy3 | `Tencent-Hunyuan/Hy3` | 404（免费 API 已下架）/ `tencent/hy3` 也 400 | **false** | 仅自部署（vLLM/SGLang），无 API 推理 |
| MiniMax-M3 | `MiniMax/MiniMax-M3` | 400 "has no provider supported" | **false** | 仅自部署，无 serverless 推理 |

**决策**：token 本身正常（Ling-3.0-flash / DeepSeek-V4-Pro 均返回 200），但这 3 个模型在 ModelScope **均不提供 serverless 推理 API**（均为开源权重、需用户自备 GPU 部署）。故从 keys.json 的 modelscope key **移除**这 3 条，避免污染模型列表、运行时恒失败。modelscope key 现 13 模型全部可达。

如未来要接入这 3 个模型，需走自部署（vLLM/SGLang 起本地 OpenAI 兼容服务）→ 加独立 key，而非 modelscope serverless token。

## 关键约束（实测）
- ModelScope 推理 API **必须传完整 Model-Id**（如 `Qwen/Qwen3-VL-235B-A22B-Instruct`），短名 → 400
- 需要真实 token（401 实测），`modelscope` key 内 `key` 字段即真实 token
- 条目字段必须用 **`name`**（非 `model`），`scope` 为数组 `["llm"]`/`["vl"]`，否则 `key_store` 跳过
