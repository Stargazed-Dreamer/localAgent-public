## A. B1 拖拽按单击语义选中被拖项

**确认决策（用户原话修正后的设计）**：已勾选的不管；触发一次被拖动项的"单击"操作——多选模式就自动勾上，单选模式自然消掉其他项的勾选。

**铁证**（已复核属实）：`L208-240:file_table_widget.py` `startDrag()` 不勾选；`L329-348` `get_drag_filenames()` 按勾选集携带（无勾选时只带焦点行）；`L92-111` `mousePressEvent()` L101 `indexAt` 可取被按下行；`L293-298` `_set_row_check` / `L300-305` `_clear_all_checks` 可复用。（原报告误把 `_set_row_check` 写成 L283-291，该范围实为 `_toggle_row_check`，已修正。）

**【实现草案】**：
- `mousePressEvent` 末尾：`self._press_row = index.row() if index.isValid() else -1`
- `startDrag()` 取文件名前：
  ```python
  row = self._press_row if getattr(self, "_press_row", -1) >= 0 else self.currentRow()
  if row >= 0:
      if self._multi_select_mode:
          self._set_row_check(row, True)          # 多选：只勾被拖项，不动其它
      else:
          self._clear_all_checks()                # 单选：清其它
          self._set_row_check(row, True)          # 再勾被拖项（单击语义）
  ```
- 之后照旧 `get_drag_filenames()`。

## E. B2 会话机制（标签页）— 已确认全部要点

**确认决策**：
1. 顶部加浏览器式标签页，可切换/开启/关闭多个会话；每个会话 = 一个源文件夹；开启哪些会话决定哪些文件夹被分类。
2. 关闭会话前弹窗确认是否删除；确认后执行删除（**仅删除会话保存的进度与状态，已移动到目标目录的文件结果不变**）。
3. 手动保存触发方式**两者都要**（Ctrl+S 与"保存会话"按钮）；**多会话不允许同时触发**（一次只一个会话跑 AI 预测/保存）。
4. 会话存储采用**每会话一文件**；应用启动时**自动恢复**上次所有打开的标签页。
5. 保存频率：不在每次分类时保存；仅在「关闭会话」或「用户手动触发」时落盘，**不询问保存到哪个配置文件**。

> ⚠️ 待补充确认：**直接关闭整个应用窗口**（closeEvent）时是否静默保存所有活动会话？第 5 条只确认了"关闭会话/手动触发"两个时机，若不保存，直接关程序会丢失上次保存以来的进度，且第 4 条的自动恢复将无源可恢复。已列入 `待对齐清单.md` N1。
>
> 另注：`改造执行依赖报告.md` §2.2 的旧 B2 方案（state.json 分桶 + 每次分类防抖自动保存）**已被本节整体取代**，执行时勿照旧方案做。

**【实现草案】**：
- 顶部 `QTabBar` +「+」新建会话；每个 tab 对应：
  ```python
  Session = {
    "source_dir": str,
    "categories_snapshot": [...],
    "current_categories": {fn: cat},
    "predictions": {fn: {...}},
  ```

- 切换 tab → 载入该会话状态到主界面（`self.files` 重扫 source_dir 并套用映射）。

## F. R1 流式审核窗口 — 已确认要点

**确认决策**：
- 用户触发 AI 审核后，弹出一个**模态**窗口展示分类进度（模态 = 阻塞主窗口，用户此时不能做其它操作也不能切换 tab，必须等 AI 跑完；但用户**可以选择中断**）。
- 窗口内实时决策：对 AI 分类的某一项「接受」或「调整」。
- 信息展示：(a) 基础信息（类型/文件名/大小/修改时间）；(b) AI 预测信息（预期分类 + 置信度）；(c) 交互反馈：用户更改并接受后，该项从当前待审列表清掉（AI 与用户流式并行处理，不阻塞后续预测项）。
- 跳过操作：流式界面中可跳过（不选任何分类）。

**【实现草案】**：
- `PredictThread`（`worker_threads.py:62-130`）改为逐条 emit 进度（扩展现有 `progress` 信号为「单条预测完成」信号，携带 `{filename, category, confidence}`）。
- ⚠️ **可中断标志需从零新增**：已复核 `worker_threads.py` 全文，PredictThread 与 MoveFilesThread **目前都没有任何 stop/interrupt 机制**（原文档"参考 MoveFilesThread 的 `self._should_stop`"为捏造引用，已修正）。做法：`PredictThread.__init__` 加 `self._should_stop = False` + `request_stop()` 方法，`run()` 在每批/每条预测前后检查标志并提前退出。
- 新增 `StreamReviewWindow`（模态 `QDialog`）：收到每条预测即插入一行显示 (a)(b)；行内「接受 / 调整(下拉改分类) / 跳过」；接受/调整→写入 `current_categories` 并从待审列表移除；跳过→标记 `skipped` 并移除；提供「中断」按钮置位中断标志。
- 预测线程继续，窗口持续接收，已处理项即时出列（模态但不阻塞线程内后续预测）。

## H. R2 专门审核界面 — 已确认骨架

**与 R1 的关系（已确认 Q6）**：两阶段分离——R1（流式模态窗口）在 AI 预测时先定每项的分类（接受/调整/跳过）；R2 在其后由「审核」按钮打开，做逐类最终核对（锁定分类、仅可跳过、标"已审"）。两阶段顺序执行，不混用。

**确认骨架**：
- "审核并移动"按钮拆为「审核」+「移动」两步；「审核」打开专门审核界面。
- 分步骤审核：一次只展示一个分类目标涉及的所有文件。
- 列表展示：每个文件的源/目标 + 详细信息（大小/修改时间/文件名/类型）。
- 审核操作：每次只展示一个分类目标类别；用户可跳过某些文件，**但此时不能更改其当前分类目标**。
- 跳过处理：当前审核结束后，跳过的文件自动清除分类（无所属）；**重新分类回主窗口用拖拽/右键，或再用 AI 预测，R2 界面内不提供重分功能**（已确认 Q8）。
- 状态标注：审核通过的文件标"已审"；主表格新增一列展示"已审/未审"。**"已审"仅由 R2 通过产生，R1 的接受只是暂定分类、不标已审**（已确认 Q9）。
- 最终移动：按「移动」按钮→弹窗**仅询问确认**是否移动所有已审文件，不再展示其它信息。**实际仅移动标为"已审"的文件（未审项不动）**（已确认 Q10）。
