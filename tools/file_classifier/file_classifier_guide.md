# 文件自动分类工具 — 操作指引

> 工具入口：`uv run python tools/file_classifier/classifier_gui.py`
> 配置文件：`tools/file_classifier/categories.json`
> 状态记忆：`tools/file_classifier/state.json`

## 工作流

```
┌─────────────┐    ┌──────────────┐    ┌──────────────────┐    ┌──────────────┐    ┌─────────────┐
│ 1. 扫描目录  │ →  │ 2. 手动分类   │ →  │ 3. AI预测空缺项  │ →  │ 4. 审核并移动 │ →  │ 5. 文件移动  │
│ 选源目录扫描 │    │ 拖文件到分类  │    │ LLM 预测分类     │    │ 覆盖/跳过/确认│    │ 按分类移动   │
└─────────────┘    └──────────────┘    └──────────────────┘    └──────────────┘    └─────────────┘
                                            │
                                            ├─ 文件：predict_categories（基于文件名+扩展名+内容）
                                            └─ 文件夹：classify_folder（类交互式协议，可请求读取嵌套文件夹）
```

### 详细步骤

1. **扫描目录**：在顶部"源目录"输入框输入或点"浏览..."选择目录，点"扫描文件"。文件夹置顶显示，其余按修改时间倒序。GUI 会自动记忆上次源目录、分类配置和分类映射，下次启动自动恢复，无需手动重新加载。

2. **手动分类**：从左侧文件列表勾选若干文件（复选框），拖拽到右侧分类目标区。这一步创建"分类映射"供 LLM 学习你的分类意图。至少给 2-3 个分类各拖 1-2 个文件效果最好。手动分好的分类映射也可直接保存复用，不一定要给 LLM。

3. **AI预测空缺项分类**：点"AI预测空缺项分类"按钮，将分类映射 + 剩余未分类文件信息发给后端 LLM 池预测。文件和文件夹分别走不同协议：
   - **文件**：基于文件名+扩展名+（可选）内容摘要预测
   - **文件夹**：走类交互式无状态协议（见下文"文件夹分类说明"）

4. **审核并移动**：点"审核并移动"打开审核对话框，可逐个修改预测分类或跳过文件。确认后按分类配置中的真实目录路径移动文件。冲突时可选覆盖/跳过/重命名（文件夹支持合并）。

5. **完成**：文件移动到分类目标目录，分类结果自动标记"已处理"写入 state.json，后端 <data_drive>:/DownloadscanAction 扫描时跳过已处理条目。

## 按钮说明

### 顶部工具栏

| 按钮 | 作用 |
|------|------|
| 源目录输入框 | 输入或粘贴要扫描的目录路径，回车即扫描 |
| 浏览... | 弹出目录选择对话框 |
| 扫描文件 | 扫描源目录顶层条目（文件+文件夹），文件夹置顶显示 |
| 加载分类配置 | 从 JSON 文件加载分类配置（name/path/extensions） |

### 左侧文件列表

| 元素 | 作用 |
|------|------|
| 面包屑导航 | 显示当前路径层级，点击某段直接跳转到该目录 |
| 上一级按钮 | 返回上一级目录（基于导航历史栈，也可按 Backspace 键） |
| 文件列表表格 | 显示条目信息：复选框/文件名/类型/大小/修改时间/创建时间/当前分类/预测分类/置信度。列头可拖动重排，顺序自动记忆 |
| 类型列 | 显示系统图标 + 友好类型描述（如"JPG 图片""PDF 文档""文件夹"） |

### 右侧分类目标区

| 按钮 | 作用 |
|------|------|
| 添加分类 | 新增一个分类（输入名称） |
| 删除分类 | 删除当前选中的分类 |
| 设置路径 | 为分类设置真实移动目标目录（path 为空=暂存分类，不移动） |
| 分类列表 | 拖放目标区，拖拽文件到此即分配到该分类 |

### 底部操作栏

| 按钮 | 作用 |
|------|------|
| AI预测空缺项分类 | 将分类映射+未分类文件信息发给 LLM 预测分类（文件+文件夹分别处理） |
| 审核并移动 | 打开审核对话框，确认后移动文件到分类目标目录 |
| 保存分类映射 | 保存当前分类配置+已分配的分类映射为 JSON，供未来复用（不限于 LLM，可直接加载使用） |
| 加载分类映射 | 加载之前保存的分类映射配置 |
| 帮助 | 用系统默认程序打开本操作指引文档 |

## 快捷键与交互模型

### 鼠标交互（反选语义）

| 操作 | 作用 |
|------|------|
| **单击（释放时）** | 翻转该行复选框（反选语义：勾选→取消，取消→勾选），并更新锚点为当前行。toggle 在鼠标弹起时触发，拖拽不会误触发 |
| **双击** | 打开对象：文件夹→进入其内部列表；文件→用系统默认程序打开 |
| **shift+单击** | 从锚点行到当前行逐行取反复选框（批量翻转一段行的选中状态） |
| **ctrl+单击** | 打开对象（同双击，保留的旧交互方式） |
| **ctrl+enter** | 弹出详情对话框，显示完整信息（文件：类型/大小/时间/分类/置信度；文件夹：内部文件数/扩展名分布/嵌套深度） |
| **右键** | 弹出上下文菜单（4 组 10 项，见下文） |
| **拖拽** | 携带所有勾选行的文件名到分类区；无勾选行时只拖当前焦点行。拖拽时只显示小虚线框光标，不显示整行内容 |
| **拖动列头** | 自由调整列的左右顺序（如把"类型"列拖到前面），顺序自动记忆 |

### 键盘交互

| 按键 | 作用 |
|------|------|
| **Enter / Return** | 打开当前焦点行对象（文件夹→进入，文件→默认程序打开） |
| **Backspace** | 返回上一级目录 |
| **Space** | 翻转当前焦点行的复选框（选中/不选中切换） |
| **ctrl+enter** | 弹出详情对话框 |

> **设计要点**：复选框=真选中。右键菜单和拖拽都作用于"勾选行"（无勾选时回退焦点行）。selectionModel 仅用于焦点/视觉高亮，不用于"选中"。

### 右键菜单（4 组 10 项）

**组 1 — 打开**
- 打开：用系统默认程序打开（等同双击/Enter）
- 在资源管理器中显示：打开资源管理器并选中该文件
- 查看详情：弹出详情对话框（等同 ctrl+enter）

**组 2 — 分类**
- 分配到分类 ▶：子菜单列出所有分类，点击即分配
- 重置分类：清除该条目的已处理状态（让后端重新扫描）+ 清除当前分类/预测

**组 3 — 跳过**
- 跳过·取消跳过：切换跳过状态（跳过的文件不参与预测和移动）
- 清除分类：清除当前分类标记（不重置已处理状态）

**组 4 — 复制**
- 复制路径：复制绝对路径到剪贴板
- 复制文件名：复制文件名到剪贴板

### 详情对话框（ctrl+enter）

- **文件**：名/路径/类型/大小/修改时间/创建时间/当前分类/预测分类/置信度/状态 + [打开][在资源管理器显示][复制路径]按钮
- **文件夹**：同上 + 内部文件数/扩展名分布/嵌套深度/总大小
- **ESC** 关闭对话框

## 文件夹分类说明

文件夹作为整体参与 LLM 分类，内部文件不拆分仅作辅助分析。

### 类交互式无状态协议

文件夹走 `classify_folder` 协议，与文件的 `predict_categories` 不同：

1. **首次调用**：发送文件夹名 + 顶层文件列表（最多 30 个）+ 扩展名分布 + 调用次数=1/15
2. **LLM 返回**：`{classification, confidence, need_more: [子文件夹路径], reason}`
3. **need_more 非空**：补全请求的子文件夹内容，重新调用（调用次数+1，不含过去上下文但含计数）
4. **循环**直到 LLM 给出最终分类或达上限

### 协议参数上限

| 参数 | 上限 | 说明 |
|------|------|------|
| 最大调用次数 | 15 | 达上限标记"未知" |
| 累计最大文件数 | 1500 | 超出截断标记 truncated |
| 单文件名最大字符 | 150 | 超长截断附加"…(截断)" |
| 单次请求文件夹数 | 10 | need_more 截断到 10 个 |
| Token 预算 | 180k | 累计达上限强制停止扩展 |
| 单次 prompt 硬上限 | 195k 字符 | 超出截断 |

### 降级机制

- LLM 不可用 → 规则匹配（取能匹配到分类的、count 最高的扩展名）
- 达调用次数/token 上限 → 标记"未知"或基于已有信息分类（置信度*0.7）

## 文件夹移动冲突

文件夹冲突支持三种处理方式（不支持覆盖，避免误删目标文件夹）：

| 模式 | 说明 |
|------|------|
| 跳过 | 不移动，保留源文件夹 |
| 重命名 | 加编号后缀（如 `folder_1`、`folder_2`） |
| 合并 | 将源文件夹内容逐个移动到目标文件夹，内部文件冲突跳过；合并后删除空源文件夹 |

文件冲突保持原有模式：覆盖/跳过/重命名。

## 状态持久化

`tools/file_classifier/state.json` 记录以下信息，GUI 和后端 <data_drive>:/DownloadscanAction 共享：

### 分类即已处理

文件/文件夹被分类并移动后，自动调 `state_manager.mark_classified(path, category)` 标记已处理。后端 <data_drive>:/DownloadscanAction 每 5 分钟扫描下载文件夹时，读取 state.json 跳过已处理条目，避免重复推送。

### 暂存分类

分类配置中 `path` 为空的分类是"暂存分类"。分配到暂存分类的文件不移动，但标记已处理（适合长期放置但不移动的文件）。

### 重置分类

右键菜单"重置分类"清除该条目的已处理状态（`state_manager.reset_classification(path)`），让后端重新扫描该文件。

### 其他记忆项

| 字段 | 说明 |
|------|------|
| `classified_files` | 路径 → {category, timestamp} 已处理条目 |
| `column_widths` | 列名 → 宽度，记忆用户调整的列宽 |
| `column_order` | 列视觉顺序（logical index 列表），记忆用户拖动列头重排的顺序 |
| `last_source_dir` | 上次打开的源目录，下次启动自动恢复 |
| `loaded_categories_config` | 上次加载的分类配置文件路径，启动自动恢复 |
| `last_sample_path` | 上次加载/保存的分类映射文件路径，启动自动恢复 |

## 置信度颜色

| 颜色 | 置信度 | 含义 |
|------|--------|------|
| 绿色 | ≥ 0.8 | 高置信度 |
| 黄色 | 0.5 - 0.8 | 中等置信度 |
| 灰色 | < 0.5 | 低置信度/未分配 |

## 分类配置格式

`tools/file_classifier/categories.json`：

```json
{
  "categories": [
    {"name": "文档", "path": "<data_drive>:\<data_drive>:\Documents", "extensions": [".pdf", ".doc", ".docx", ".txt", ".md"]},
    {"name": "图片", "path": "<data_drive>:\<data_drive>:\Pictures", "extensions": [".jpg", ".png", ".gif", ".bmp", ".webp"]},
    {"name": "暂存", "path": "", "extensions": []}
  ]
}
```

- `name`：分类名称（显示在右侧列表）
- `path`：真实移动目标目录（空=暂存分类，不移动）
- `extensions`：扩展名白名单（降级规则匹配时使用）

## 后端监控循环

后端 <data_drive>:/DownloadscanAction 每 5 分钟扫描下载文件夹（`config.toml` `[loops.download_watcher]`）：

1. 扫描顶层条目（文件+文件夹）
2. 读取 state.json 跳过已处理条目
3. 文件数超阈值（默认 15）触发分类
4. 文件走 `classify_with_disposition`，文件夹走 `classify_folder`
5. Phase 2 内容增强仅对文件生效（文件夹不参与）
6. 按 disposition 分组推送 inbox：move（可直接移动）/ inspect（需审查）/ unknown（无法分类）

配置项：

| 配置 | 默认值 | 说明 |
|------|--------|------|
| `scan_interval` | 300 | 扫描间隔（秒） |
| `file_count_threshold` | 15 | 触发分类的条目数阈值 |
| `classify_batch_size` | 50 | 单次文件分类数上限 |
| `folder_batch_size` | 10 | 单次文件夹分类数上限（文件夹成本高） |
| `content_aware` | true | 是否启用 Phase 2 内容增强（仅文件） |
