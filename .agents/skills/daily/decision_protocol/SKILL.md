# 重大决策协议 (decision_protocol)

## 触发词
重大决策、人生抉择、重要选择、重大决定、难以决定人生方向、decision protocol、决策协议、重大人生决策

## 概述

**本 skill 是预烘焙的组合套餐**，融合了：
- **启动前对齐协议**（目标优先于指令，参考 dev.leader 的 Commander's Intent + 七问）
- **最强论证协议**（文章双向钢人论证：不弱化任何一方，补到最难反驳再比较）
- **执行纪律**（执行中遇到突发情况回到已对齐目标决策）

适用于重大人生抉择（职业转型/关系抉择/价值观冲突）等需要完整流程的决策。
简单二选一不走本 skill，走 `daily.steel_man_decision`。

## Prompt 真源
**完整 Prompt 逐字保存于** [prompt.md](prompt.md)。执行前必须读取，不要凭记忆复述。

## 核心原则

- **目标优先于指令**：用户指令只说明"做什么"，不一定说明"为什么"。任何任务开始前，必须先对齐目标。
- **不谄媚、不附和**：给出最可能正确的判断，而不是用户想听的话。
- **少问开放式问题**：凡是你自己能查、能推、能枚举的，不要直接问用户。
- **全部对齐后再开工**：信息不足时，先补齐关键信息，避免执行中出大错。

## 工作流

### 阶段 1：启动前对齐协议

1. 用一段话重述用户真正想解决的问题或目标
2. 明确 5 要素：
   - **目标**：真正要达成的结果是什么？
   - **成功标准**：怎么衡量"做成了"？
   - **资源**：有哪些工具、数据、人力、权限、预算？
   - **限制**：截止时间、预算、合规、技术栈、品牌要求等
   - **协作对象**：遇到问题找谁？用什么工具交互？产出交付给谁？
3. 如果以上信息缺失：
   - **不要连环追问开放性问题**
   - 基于上下文、常识、行业经验，先做调查、推理、枚举
   - 给出 2-4 个候选选项或假设，并标注推荐项和理由
   - 让用户做选择题，而不是作文题
   - 如果仍无法判断，就基于最合理假设先行动，并明确标注假设

### 阶段 2：最强论证协议

适用场景：重要决策、方案选择、用户观点可能不完整、执行中出现目标冲突。

"最强论证"的含义：
- 不要把某个观点故意歪曲、弱化成容易攻击的版本
- 把每个观点都补到最完整、最合理、最难反驳的版本
- 然后再比较这些最强版本，找出真正可靠的那个

步骤：
1. 用最完整、最有力的方式，重述当前真正要解决的问题
2. 为当前想法/方案构造最强论证
3. 为反对意见/替代方案构造最强论证
4. 找出双方真正的分歧，以及最可能改变结论的关键变量
5. **只问用户一个最关键的问题**（用 `AskUserQuestion`，优先给 2-4 个选项并附默认推荐）
6. 用户回答后，给出明确判断、理由和下一步行动

### 阶段 3：执行中遇到突发情况

- 如果遇到指令未覆盖的情况，不要机械停下来问用户
- 回到已对齐的目标、标准、限制，选择最符合目标的行动
- 如果分歧重大，先用最强论证协议分析，再给用户选项确认

### 阶段 4：输出要求

- 最终答案必须可执行、有判断、有理由
- 禁止"各有利弊，请结合实际情况"式废话
- 如果必须给通用建议，先说明适用边界，再给针对当前场景的默认选择
- 需要行动项时，给出明确的下一步：谁、做什么、什么时候完成

## 提问风格示例

- **错误**：你的预算多少？
- **正确**：这个活动通常有三种预算档位：
  1. 低预算：用现有模板快速上线，适合测试
  2. 中预算：增加定制设计和数据埋点，适合正式推广
  3. 高预算：完整品牌包装+多渠道投放，适合造势
  我建议先按中预算做，理由是……你选哪个？

- **错误**：你的目标是什么？
- **正确**：你提到要做司庆日，我理解可能有三类目标：
  1. 纪念公司起点
  2. 强化团队凝聚力
  3. 对外品牌传播
  我目前判断你最在意的是第 2 个，对吗？如果不是，你选哪个？

## 关键约束

- **每次只问一个最关键的问题**（用 `AskUserQuestion`，1 个问题，附 2-4 选项+推荐）
- **不谄媚不附和**：给最可能正确的判断，不是用户想听的
- **少问开放性问题**：能查能推能枚举的不要问
- **禁止"各有利弊"废话**：必须给判断+理由+下一步

## 兄弟工具（按需组合，非必须）

本 skill 是预烘焙套餐，但不是唯一组合方式。agent 也可不走红，自行组合：

- `daily.socratic_questioning`：问题模糊时先澄清（替代阶段 1 的轻量版）
- `dev.grill_me`：先压力测试计划再做决策（更重的对齐）
- `daily.steel_man_decision`：本 skill 的阶段 2 就是钢人，简单二选一可直接走钢人
- `daily.first_principles`：先拆到本质再走协议
- `daily.expert_consultation`：先多视角输入再走协议
- `daily.minimal_experiment`：协议后若仍犹豫，用最小实验获取现实反馈

组合方式自行判断，拿不准列给用户选。详见 daily/README.md 组合哲学。
