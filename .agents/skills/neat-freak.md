# 文档洁癖 (neat-freak)

## 触发词
sync up、tidy up docs、update memory、clean up docs、/sync、/neat、同步一下、整理文档、整理一下、更新记忆、梳理一下、收尾、这个阶段做完了、新人能直接上手

## 概述
会话结束后对项目文档进行系统性审查与同步，确保知识在所有载体间一致、准确、无冗余。核心哲学：**你是知识编辑，不是知识记录仪** — 只保留对 AI agent 和人类开发者真正有用的信息，删除过时内容，合并重复内容，修正矛盾内容。

## 核心哲学

### 知识编辑 vs 知识记录

- ❌ 不是把会话内容原封不动复制到文档里
- ❌ 不是给每个细节都加一条记录
- ✅ 是判断哪些知识值得保留、以什么形式保留、放在哪里
- ✅ 是让下一个 agent 或新队友拿起文档就能上手，不需要再来问你

### 三类知识

| 类型 | 定义 | 存放位置 | 示例 |
|------|------|----------|------|
| **项目知识** | 关于项目结构、架构、约定的持久事实 | `AGENTS.md` | "PaddlePaddle 必须先于 torch import"、"截图必须传 format=base64" |
| **功能知识** | 关于某个功能如何使用的工作流 | `.agents/skills/*.md` | "记账 Skill 的工作流是：准备文件→运行脚本→核对→应用" |
| **操作知识** | 本次会话中发现的临时性发现或变通方案 | 不持久化，除非有长期价值 | "今天发现某个 API 返回格式变了" → 如果是永久变化则更新到项目知识，否则不记录 |

### 反膨胀原则

1. **只增不删是最大的技术债**：过时信息比没有信息更危险
2. **一处真相**：同一事实只在一个地方维护，其他地方引用它
3. **删除优先于注释**：过时的内容直接删，不要加"已废弃"标记
4. **新增前先找归属**：新信息应该放到已有文档的哪个位置？而不是新建文件

## 审查流程

### 第 1 步：扫描变更

回顾本次会话中做了什么：

1. **新增了哪些文件？** — 代码、脚本、配置
2. **修改了哪些文件？** — 特别是 `server/`、`tools/`、`.agents/skills/` 下的文件
3. **删除了哪些文件？** — 是否有文档还引用了已删除的文件
4. **发现了什么新知识？** — 踩坑、变通方案、API 变化

### 第 2 步：审查 AGENTS.md

逐项检查 `AGENTS.md` 是否需要更新：

- [ ] **项目简介** — 新增了什么能力？描述是否仍然准确？
- [ ] **技术栈** — 新增了依赖？版本号变化？
- [ ] **关键约束** — 新发现了兼容性问题？旧约束是否已解决？
- [ ] **API 常见陷阱** — 新踩了坑？需要新增警告？
- [ ] **项目结构** — 新增了目录或文件？旧结构是否已删除？
- [ ] **MCP 接入** — 工具数量变化？端点变化？

**判断标准**：只更新对 agent 或开发者有实际影响的信息。内部实现细节不写，除非它影响使用方式。

### 第 3 步：审查 Skill 文件

对每个本次会话涉及或影响的 Skill：

- [ ] **触发词** — 是否需要新增触发词？现有触发词是否仍然准确？
- [ ] **工作流** — 步骤是否有变化？新增了步骤？步骤顺序变了？
- [ ] **依赖** — 新增了依赖？旧依赖已移除？API 路径变了？
- [ ] **关键规则** — 新增了约束？旧规则不再适用？
- [ ] **输入/输出** — 格式变了？目录变了？

**判断标准**：Skill 是给 agent 执行用的，工作流必须精确可执行。模糊的描述必须细化。

### 第 4 步：审查 _index.md

检查 `.agents/skills/_index.md`：

- [ ] **Skill 列表** — 新增的 Skill 是否已添加？旧的是否需要更新？
- [ ] **API 接口表** — 新增了接口？接口签名变了？
- [ ] **项目结构** — 目录树是否反映当前状态？

### 第 5 步：审查记忆

- `memory_list` 列出所有记忆（含摘要，无需逐个读取）
- 检查每条记忆：描述是否准确？内容是否过期？是否还需要保留？
- 超过30天未更新的孤立记忆用 `memory_cleanup_orphaned` 清理
- Skill 工作流中写死的动态数据（如"已清理6条"）应迁移到记忆中，skill 文件只保留工作流

### 第 6 步：审查 MCP 工具使用情况（数据驱动）

- `mcp_stats` 获取工具调用统计
- **识别低频工具**：调用次数为 0 或极少的工具，考虑是否应排除出 MCP
- **检查上游修复**：VL 等临时禁用的工具，检查 PaddlePaddle 是否已修复 PIR bug
- **发现高频错误**：error_count 高的工具可能有问题需要修复
- **调整排除列表**：根据数据调整 `server/main.py` 的 `_mcp_exclude`

### 第 7 步：审查测试

检查 `tests/` 目录：

- [ ] 新增的模块是否有对应测试文件？
- [ ] 已有测试是否因代码变更而需要更新？
- [ ] 测试是否能通过？（`uv run python -m pytest tests/ -v --tb=short`）

### 第 8 步：审查配置

检查配置相关文件：

- [ ] `config.example.toml` — 新增的配置项是否有模板？
- [ ] `server/config.py` — `get_*_config()` 是否支持新配置？
- [ ] `.gitignore` — 新的敏感文件/目录是否已排除？

### 第 9 步：审查 GUI 监控面板

检查 `client/panels/monitoring.py`：

- [ ] 新增的模块/状态是否在面板中展示？
- [ ] 旧的展示项是否仍然有效？

## 同步矩阵

以下文件之间存在依赖关系，修改一处必须检查其他处是否需要同步：

| 修改了 | 需要同步检查 |
|--------|-------------|
| `.agents/skills/xxx.md` | `.agents/skills/_index.md` |
| `.agents/skills/_index.md` | 无需额外同步（唯一索引） |
| `server/xxx.py`（新模块） | `server/main.py`（注册路由）、`tests/test_xxx.py`、`/health`、`AGENTS.md`（项目结构） |
| `server/xxx.py`（改接口） | 对应 `.agents/skills/xxx.md`（工作流+依赖）、`_index.md`（API 表）、`tests/test_xxx.py` |
| `tools/xxx/`（新脚本） | 对应 `.agents/skills/xxx.md`（依赖+工作流）、`_index.md` |
| `AGENTS.md` | 无需额外同步（这是终端文档） |
| `config.example.toml` | `server/config.py`（确保支持新配置） |
| `.agents/rules/project_rules.md` | `.trae/rules/project_rules.md`（Trae 镜像副本需同步） |

### 同步铁律

1. **`.agents/skills/` 是唯一 Skill 目录**：所有 Skill 文件都在 `.agents/skills/` 下
2. **`_index.md` 是唯一索引**：`.agents/skills/_index.md` 是所有 Skill 的索引
3. **API 变更三处同步**：接口签名变了 → Skill 文件 + _index.md + 测试文件 都要更新

## 执行原则

### 做什么

1. **删除过时信息**：已删除的功能、已修复的 bug、已变更的 API
2. **更新变化信息**：新版本号、新路径、新参数、新约束
3. **合并重复信息**：同一事实出现在多处时，选一个权威位置，其他引用
4. **补充缺失信息**：新功能缺少文档、新约束没有记录

### 不做什么

1. **不重写**：只改需要改的，不要"顺手"重写整个文件
2. **不添加注释**：不在代码中添加解释性注释
3. **不创建新文档**：除非确实需要新的 Skill 文件，否则不新建 .md
4. **不记录临时状态**：本次会话的调试过程、临时变通方案，除非有长期价值
5. **不修改代码逻辑**：文档审查只改文档，不改代码

### 修改粒度

- **精确修改**：用 Edit 工具精确替换需要更新的内容
- **不要全文重写**：即使文档需要多处修改，也逐处精确编辑
- **验证修改**：每次修改后确认文件内容正确

## 依赖

| 依赖 | 路径/接口 | 说明 |
|------|----------|------|
| 项目指引 | `AGENTS.md` | 项目结构和规范（终端文档） |
| Skill 目录 | `.agents/skills/` | Skill 定义文件 |
| Skill 索引 | `.agents/skills/_index.md` | 所有 Skill 的索引 |
| 变更清单 | `.agents/rules/project_rules.md`（规范源）、`.trae/rules/project_rules.md`（Trae 镜像） | 功能变更检查清单 |
| 测试目录 | `tests/` | 测试文件 |
| 配置模板 | `config.example.toml` | 配置项模板 |
| GUI 监控面板 | `client/panels/monitoring.py` | 状态展示面板 |

## 输入/输出

- **输入**：本次会话的变更上下文（隐式，通过回顾会话获得）
- **输出**：同步后的文档文件 + 审查报告
