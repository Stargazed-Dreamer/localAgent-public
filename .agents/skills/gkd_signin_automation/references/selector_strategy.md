# GKD 选择器策略

## 选择顺序

1. 目标自身稳定 `vid` 或完整资源 `id`。
2. 稳定且语义明确的 `text`/`desc`，附 `clickable=true`、`visibleToUser=true`。
3. 目标无文字时，用一个稳定近邻或祖先消歧，关系链保持尽可能短。
4. WebView 或混合页面只有在没有更直接属性时才使用结构关系。
5. `position` 仅用于几何固定、分辨率边界已确认且存在稳定匹配锚点的页面。

`@` 标记实际动作节点。命中文字子节点但父节点才可点击时，优先直接选择最近的稳定可点击祖先；无法直接描述时再用短关系链把 `@` 放在祖先。

## 跨版本稳定性检查

同一动作至少比较以下快照：

- 操作前与操作后。
- 未签到与已签到。
- 正常加载与慢加载。
- App 更新前与更新后（可获得时）。

属性只在一份快照出现时，不能称为稳定。父子 `index`、`childCount` 和十几层祖先路径容易随布局重排变化，应作为最后的消歧信息。

## 等价规则

`id="com.example:id/check"` 与 `vid="check"` 通常指向同一节点。把两者写成两个 rule 会产生两个独立动作；`actionMaximum=1` 不能替代去重设计。要增强约束，应在同一选择器中增加可见性、可点击性或上下文，而不是并列重复点击规则。

## 状态与时间

优先匹配“页面已经加载完成”的语义节点，再点击动作目标。固定延迟只能覆盖已测量的加载区间，无法保证网络慢或 App 改版时仍正确。

签到后如果节点的 `id/vid/text/desc/clickable/checked` 全部不变，只换图片资源，GKD 无障碍选择器无法区分两种状态。此时有三个诚实选项：

- 接受每次 App 会话最多触发一次。
- 寻找页面其他位置可访问的“已签到”信号，加入排除条件或改变入口流程。
- 把自然日去重交给有状态的外部编排器。

## 验证标准

- 选择器匹配数符合预期，通常是 1。
- Activity 与应用包名正确。
- 动作日志只有一个预期 rule index。
- 页面业务状态确认成功，不能只看 `ActionResult(result=true)`。
