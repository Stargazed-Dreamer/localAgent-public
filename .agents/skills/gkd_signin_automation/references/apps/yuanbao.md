# 元宝

## 用户确认流程

任务要求检查模型模式，然后反复执行“我们 -> 福利中心 -> 对话任务入口 -> 输入 -> 发送 -> 回到福利中心”。每日包含 `1+3+3` 次对话任务，至少进入福利中心 8 次，且“去提问”和“去写作”使用不同输入。

## 结论

这是有状态循环、计数、输入和外部模型响应共同驱动的流程，超出 GKD 无状态规则的舒适区。强行拆成大量 `preKeys` 和页面规则会难以恢复中断，也无法可靠证明 1+3+3 计数正确。

保持人工是合理方案。若以后自动化，应单独做 C 级状态机：显式保存任务计数、当前入口类型、发送文本、福利中心奖励状态和失败恢复点；不要把它并入通用 GKD 签到订阅。
